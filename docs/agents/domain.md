# Domain Docs

How engineering skills should consume domain documentation in this repo.

## Before exploring

Read `GLOSSARY.md` at the root when present. Read relevant ADRs in `docs/adr/` before changing an area. If these files do not exist yet, proceed without flagging their absence; create them only when domain terms or decisions are resolved.

## Layout

This is a single-context project. Keep one root `GLOSSARY.md` and project-wide ADRs in `docs/adr/`.

## Use the glossary

Use glossary terms in issue titles, proposals, hypotheses and tests. If a needed concept is missing, note it for domain modeling.

## Flag ADR conflicts

If a proposal conflicts with an existing ADR, state the conflict and why the ADR may need to be reopened.
